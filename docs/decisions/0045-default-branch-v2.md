# 0045 默认分支切换为 v2

- 状态：已接受（2026-11-21）；取代 [0044](0044-implementation-and-branches.md) 中“发布 2.0.0 时切换默认分支”的条款
- 同时解决 [0010](0010-orphan-branch-v2.md) 中“`v2` 何时、以何种方式成为默认分支”的待定问题

## 背景

- Amp orb 的 `.agents/setup` 只对项目的默认分支生效：新 orb 从默认分支克隆，并执行其中的 setup。默认分支是 `main` 时，`v2` 上的环境准备（Rust 工具链）对新 orb 不生效。
- 0044 把切换推迟到 2.0.0 发布，Rust 版开发期间的 orb 环境准备会一直不生效。

## 决定

- GitHub 默认分支立即切换为 `v2`。
- `main` 冻结为 1.x，只修严重问题（0044 中的这一条不变）。`main` 与 `v1` 当前指向同一提交，保留 TS 1.x 历史，不删除。
- 0044 的其余条款不变：`v2` 是 Rust 版开发主线，各阶段 PR 合入 `v2`。

## 影响

- 新 clone、默认 PR 目标、新 orb 都指向 `v2`。在 Rust 实现（P0）合入前，`v2` 只含设计文档，新 orb 拿到的是文档而不是 1.x 代码；需要 1.x 代码的人应检出 `main`。
- `.github/workflows/ci.yml` 只在 `main`、`v1`、`feat/**` 上运行，不覆盖 `v2`。`v2` 的 CI 在 P0 引入 Cargo 工作区时一起加入。
- 切换时没有打开中的 PR 需要重定向。
