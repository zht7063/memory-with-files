# MWF — Memory With Files (1.0 alpha)

Project memory for coding agents, stored as plain Markdown files under `.mwf/` in your repository. Files are the source of truth; `index.db` (SQLite, FTS5) is a derived, rebuildable cache.

> **Status: `v1` integration branch, PR2 (CLI layer).** MWF 1.0 is a ground-up rewrite. `src/core` and `src/cli` are implemented; `src/mcp` and `src/hooks` are placeholders. The 0.x line lives on `main`.

## Layout

```
src/core    # file store, index, locking, all operations
src/cli     # structured command functions + the read-only command line (this PR)
src/mcp     # MCP server (planned)
src/hooks   # host hooks (planned)
src/bin     # the `mwf` executable: dispatch only
```

Each layer imports only the one beneath it (`cli` -> `core`, later `mcp` -> `cli`, `hooks` -> `mcp`); `tests/layers.test.ts` enforces it.

```
.mwf/
  config.toml  protocol.md  index.md  inbox.md
  handoff/<task>.md
  memory/{preferences,decisions,incidents,tasks,knowledge}/<id>.md
  index.db  state.toml (sessions)  dedup.local.toml  host.local.toml  trash/  mwf.local.lock
```

`init` has two git modes. `track` commits `.mwf/` and writes exactly three `.gitignore` lines (`.mwf/trash/`, `.mwf/index.db-*`, `.mwf/*.local.*`); `local` adds `.mwf/` to `.gitignore`. Nothing else is written outside `.mwf/`.

## Core API

```ts
import { init, add, recall, handoff, forget } from '@zht7063/mwf/core';

const ctx = { root: process.cwd() };
await init(ctx, { git_mode: 'track' });
await add(ctx, { type: 'decision', title: 'Use SQLite', body: '…', scope: { paths: ['src/core/'] } });
await recall(ctx, { query: 'sqlite', scope: { paths: ['src/core/db.ts'] } });
```

Every write takes an optional `request_id` (idempotent retry) and `wait_ms` (lock wait budget). `forget`, `purge`, `compact` and `inbox discard` preview first and execute only with `confirm: true` plus the matching `preview_token`.

Write-path rules (all enforced inside the one `runWrite`, under the project lock):

- **Secret scanning**: a write that would introduce a likely secret (cloud / code-host / payment API keys, private keys, JWTs, URLs with embedded passwords, `key = <random value>` assignments, …) is rejected with `SECRET_DETECTED` before anything is written; the error lists rule, path and line with a redacted sample, never the value. Only newly introduced matches count, so an already-leaked record can still be forgotten, purged or edited elsewhere. There is no override.
- **`index.md`** is regenerated by every write that changes records or handoffs, as part of the same intent/recovery flow (written first, so no state with the new record has a stale index); `reindex` still rebuilds it from scratch.
- **`dedup.local.toml`** holds the request_id dedup table (24 h / 1000 entries). It is machine-local, never tracked (`.mwf/*.local.*`), and treated as empty if corrupt (`doctor` warns). `state.toml` only keeps session mapping.
- **Destructive ops** (`forget`, `purge`, `compact`, `inbox discard`) preview first and execute only with `confirm: true` plus the matching `preview_token`. `edit` is not destructive: it is guarded only by `expected_hash`.

## CLI layer

`src/cli` has one structured function per command (`init`, `bootstrap`, `recall`, `get`, `add`, `propose`, `edit`, `handoff`, `status`, `doctor`, `inbox`, `compact`, `reindex`, `forget`, `restore`, `purge`); the MCP layer will expose each as `mwf_<name>`. A function validates its input against a JSON-Schema description (unknown fields are rejected), finds the project by walking up from `cwd`, calls core and returns `{ ok: true, data }` or `{ ok: false, error: { code, message, details } }`. It never throws.

```ts
import { add, forget } from '@zht7063/mwf/cli';

const env = { cwd: process.cwd() };
const added = await add({ type: 'decision', title: 'Use SQLite', body: '…' }, env);
const preview = await forget({ ids: [id] }, env); // preview only
await forget({ ids: [id], confirm: true, preview_token: preview.data.preview_token }, env);
```

The `mwf` executable exposes only the three read-only commands; every write goes through MCP tools.

```
mwf status [--json] [--cwd dir]
mwf recall [query] [--type t]... [--status active|done|all] [--task name] [--handoffs]
           [--scope key=value]... [--limit n] [--max-chars n] [--json]
mwf doctor [--json]
```

Exit codes: `0` ok, `1` the command failed or `doctor` found errors, `2` usage error. `hook`, `mcp` and the lifecycle commands (`install`, `uninstall`, `update`) are not part of this build.

## Locking

All writes run under `.mwf/mwf.local.lock` (an `O_EXCL` file holding pid, hostname, pid namespace, start time, acquisition time, heartbeat time and a token).

- A holder on **this host and pid namespace** is reclaimed only when its pid is gone or the pid now belongs to a different process; a live holder is never reclaimed, however old.
- A holder on **another host, or in another pid namespace under the same hostname**, cannot be checked by pid, so it is reclaimed only when its heartbeat is older than `lockStaleMs` (default 30 s). Long operations heartbeat.
- **A writer whose lock was taken away aborts.** Before the intent, before every target and before the index sync / dedup registration the writer re-reads the lock; if it is no longer ours the write stops with `LOCK_LOST` and nothing more is written. The partial state is an intent, which the next lock holder recovers (roll forward, or discard). The timer heartbeat also notices a lost lock while an operation is awaiting. A small window remains between the last check and the final dedup / intent removal.
- **`doctor` reports** a live lock held longer than `lockHeldWarnMs` (default 120 s, `lock_held_long`), and a roll-forward that left a changed file in place (`rollforward_skipped`; see below).
- **Known limit: same hostname, different pid namespace.** Containers that share a hostname (`--hostname`, `--uts=host`) but not a pid namespace cannot see each other's pids. mwf records the pid namespace in the lock (Linux, `/proc/self/ns/pid`) and treats a holder from another namespace like a foreign host, so it is not reclaimed by a pid check. Where the namespace cannot be read (no `/proc`, or a lock written by an older mwf without it) two such containers look like one host: the other container's pid does not exist (or is an unrelated process) in the reclaimer's namespace, and it can wrongly reclaim a live lock. Give such containers distinct hostnames or a shared pid namespace.

**Recovery and changed files.** If a writer dies between the removals of a `forget` / `compact` / `purge`, the next lock holder rolls the remaining removals forward, but only for files that still hold the planned content. A file that was edited in the meantime is kept, and the skip is written to `.mwf/recovery.local.json` (machine-local, entries expire after 30 days). `doctor` reports each such file as `rollforward_skipped` until it is gone.
